# گزارش اشکال‌یابی و پیشنهاد توسعه — SafirCharge

**تاریخ:** ۲۰۲۶-۱۰-۲۰
**دامنه:** `cloud/` و `edge/` (Laravel 13، PHP 8.4، MariaDB 10.11) + Docker

## ۱. روش بررسی

- نصب کامل وابستگی‌ها روی PHP 8.4 و اجرای migration و seed روی **MariaDB 10.11** (همان دیتابیس production) و sqlite.
- اجرای هر دو سرور و فراخوانی **همهٔ صفحات GET** پنل ادمین، پنل شرکا، وب‌اپ مشتری و پنل ایستگاه با کاربر واقعی.
- فراخوانی **همهٔ مسیرهای POST/PUT** (بیش از ۶۵ مسیر) با ورودی خالی برای اطمینان از نبود خطای 500.
- اجرای تمام اسکریپت‌های تست موجود (`cloud/scripts/test-*.php`) و تست‌های PHPUnit.
- تست انتهابه‌انتها با **شبیه‌ساز شارژر OCPP 1.6J** که مثل دستگاه واقعی از طریق WebSocket وصل می‌شود.

## ۲. مهم‌ترین مشکل: شارژ واقعاً به دستگاه نمی‌رسید

| پیش از اصلاح | پس از اصلاح |
|---|---|
| «شروع شارژ» فقط یک رکورد در دیتابیس می‌ساخت؛ هیچ دستوری به شارژر ارسال نمی‌شد. | Edge دستور `RemoteStartTransaction` را به شارژر می‌فرستد و منتظر پاسخ می‌ماند. |
| انرژی و هزینه با فرمول «توان × زمان × ۰٫۸۵» تخمین زده می‌شد. | انرژی از کنتور خود شارژر (`MeterValues`/`StopTransaction`) خوانده و صورتحساب بر همان اساس صادر می‌شود. |
| سرور OCPP در این ریپازیتوری وجود نداشت (وابسته به پروژهٔ خارجی `C:\Project\Charger` که در دسترس نبود). | سرور مرکزی OCPP 1.6J داخلی و بدون وابستگی (`php artisan ocpp:serve`)؛ پروژهٔ خارجی همچنان با `OCPP_DRIVER=gateway` قابل استفاده است. |
| اپ آنلاین (ابر) فقط وضعیت کانکتور را «Charging» علامت می‌زد. | ابر دستور `remote_start`/`remote_stop` را برای Edge صف می‌کند؛ Edge با OCPP اجرا و نتیجه را سینک می‌کند. |
| وضعیت کانکتورها از ابر روی Edge بازنویسی می‌شد. | وضعیت زنده از `StatusNotification` شارژر می‌آید و به ابر هم سینک می‌شود. |

پیام‌های پشتیبانی‌شده: `BootNotification`، `Heartbeat`، `StatusNotification`، `Authorize`، `StartTransaction`، `MeterValues`، `StopTransaction`، `DataTransfer`، `DiagnosticsStatusNotification`، `FirmwareStatusNotification`. دستورهای خروجی: `RemoteStart/StopTransaction`، `Reset`، `UnlockConnector`، `ChangeAvailability`، `SetChargingProfile`، `GetDiagnostics`، `UpdateFirmware`، `TriggerMessage`، `Get/ChangeConfiguration`.

رفتارهای حفاظتی:
- توقف خودکار وقتی هزینه به موجودی کیف پول برسد.
- لغو خودکار شروع‌هایی که کابل در ۳ دقیقه وصل نشد (بدون هزینه).
- `StopTransaction` تکراری (پس از قطع و وصل شبکه) دوباره برداشت نمی‌کند.
- جلوگیری از شروع دو جلسه روی یک کانکتور؛ رد شروع وقتی شارژر آفلاین یا Faulted است.
- کارت RFID روی خود دستگاه بدون اینترنت از کش محلی تأیید می‌شود.

## ۴. نکات باقی‌مانده که تصمیم شما لازم است

1. **QR بدون توکن:** API محلی `authorize` با `method=qr` بدون `qr_token` هم مجوز می‌دهد (فقط با داشتن UUID کانکتور). اگر QRها توکن‌دار هستند، بهتر است توکن اجباری شود.
2. **رمز شارژرها:** رمز Basic Auth شارژر به‌صورت متن ساده در `meta` ذخیره می‌شود (برای مقایسه لازم است). برای امنیت بیشتر، OCPP Security Profile 2 (TLS) پیشنهاد می‌شود.
3. **ایستگاه‌های بدون Edge:** در production شروع شارژ آنلاین برای ایستگاه بدون Edge رد می‌شود (در محیط توسعه شبیه‌سازی می‌شود). اگر ایستگاهی شارژرش مستقیم به ابر وصل است، نیاز به سرور OCPP در ابر دارد.
4. **ارسال پیامک واقعی:** درایور GSM فعلاً `log` است؛ قبل از بهره‌برداری باید مودم/سرویس پیامک واقعی وصل شود.
5. **درگاه پرداخت:** شارژ کیف پول در اپ شبیه‌سازی‌شده است؛ اتصال به درگاه بانکی واقعی لازم است.

## ۵. پیشنهادهای توسعه (به ترتیب اولویت)

### فاز کوتاه‌مدت (آمادگی بهره‌برداری)
1. **تست میدانی با ۲–۳ مدل شارژر واقعی** (مثلاً ABB، Alfen، Delta) و ثبت تفاوت‌های فروشنده در `ocpp_message_logs`؛ تنظیم `MeterValuesSampledData` و `MeterValueSampleInterval` با `ChangeConfiguration` پس از Boot.
2. **OCPP Security Profile 2/3** (wss با گواهی، احراز شارژر با گواهی کلاینت).
3. **Smart Charging:** تقسیم توان بین کانکتورها بر اساس ظرفیت انشعاب ایستگاه با `SetChargingProfile`.
4. **رزرو واقعی روی شارژر** با `ReserveNow`/`CancelReservation` (اکنون رزرو فقط در دیتابیس است).
5. **مانیتورینگ و هشدار:** اعلان به اپراتور هنگام `Faulted`، قطع شارژر، یا قطع طولانی Edge از ابر.
6. **پشتیبان‌گیری خودکار دیتابیس Edge** و بازیابی پس از خرابی Mini PC.

### فاز میان‌مدت
7. **پشتیبانی OCPP 2.0.1** برای شارژرهای جدید (ISO 15118 / Plug & Charge).
8. **تعرفهٔ پیشرفته:** اوج/غیراوج، تعرفهٔ پارکینگ پس از اتمام شارژ (idle fee)، تخفیف اعضا و سازمان‌ها.
9. **اپ موبایل بومی** (Android/iOS) روی همان API نسخهٔ ۱ با Push Notification.
10. **داشبورد BI و گزارش مالیاتی** با خروجی Excel/PDF و تسویهٔ خودکار شرکا.
11. **به‌روزرسانی Firmware مرکزی** و زمان‌بندی آن برای ساعات کم‌مصرف.

### فاز بلندمدت
12. **OCPI** برای رومینگ با شبکه‌های شارژ دیگر.
13. **پیش‌بینی تقاضا و خرابی** با داده‌های جلسات و MeterValues.
14. **V2G / مدیریت شبکهٔ برق** (OpenADR) برای ایستگاه‌های بزرگ.
