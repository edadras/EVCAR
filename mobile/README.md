# SafirCharge — اپ موبایل مشتری (Flutter: اندروید و iOS)

نسخهٔ بومی همان وب‌اپ مشتری (`/app`) با همان طراحی (فونت وزیرمتن، راست‌به‌چپ، رنگ‌ها و چیدمان)
و دقیقاً همان منطق کسب‌وکار: اپ به API اختصاصی `‎/api/v1/mobile/*` روی سرور ابری وصل می‌شود و همهٔ
اکشن‌ها (شروع/توقف شارژ، شارژ کیف پول، خودرو، RFID، رزرو، تیکت و …) به همان کنترلرهای وب‌اپ می‌روند.

## صفحات

| بخش | توضیح |
|---|---|
| ورود / ثبت‌نام | شماره → رمز (کاربر موجود) یا کد تأیید پیامکی → تعیین رمز؛ توکن Sanctum ‏۹۰ روزه |
| پیشخان | جلسهٔ فعال با حلقهٔ درصد، موجودی، طرح ویژه، مسیریاب، دسترسی سریع، نزدیک‌ترین ایستگاه‌ها با فیلتر |
| نقشه | نقشهٔ OpenStreetMap، نشانگر ایستگاه‌ها (سبز آزاد / نارنجی پرتراکم)، جست‌وجو، فیلتر، فهرست کشویی |
| اسکن QR | دوربین واقعی (`mobile_scanner`)، چراغ‌قوه، ورود دستی کد |
| شارژر | مجوز QR/RFID/پلاک، انتخاب کانکتور مجاز، تعرفه (انرژی، اشغال، کم‌باری)، درصد شارژ فعلی، شروع شارژ |
| شارژ زنده | درصد باتری، انرژی، توان، مدت، هزینه، زمان تا شارژ کامل، هدف شارژ؛ به‌روزرسانی هر ۵ ثانیه؛ توقف |
| کیف پول | موجودی، اعتبار پاداش، باشگاه مشتریان، تراکنش‌ها (جست‌وجو/فیلتر)، افزایش موجودی → درگاه → رسید |
| سوابق | خلاصهٔ ماه، صرفه‌جویی CO₂، جلسات با جست‌وجو |
| رزرو | انتخاب ایستگاه، وضعیت زندهٔ کانکتورها، روز و بازهٔ ۳۰ دقیقه‌ای |
| مسیریاب برقی | مبدا/مقصد (جست‌وجو یا لمس نقشه)، خودرو، درصد شارژ؛ تحلیل مسیر، مصرف و برنامهٔ توقف شارژ |
| حساب | پروفایل، خودروها (افزودن/ویرایش/حذف/پیش‌فرض)، پلاک، کارت RFID (ثبت/مسدود/فعال/حذف)، رمز، تنظیمات |
| سایر | اعلان‌ها، طرح‌ها، پشتیبانی (تماس، تیکت، گفتگو، پرسش‌های متداول)، قوانین، حریم خصوصی، تأیید ورود با پلاک |

تنظیمات ظاهری (حالت تیره، رنگ برنامه) مانند وب‌اپ روی حساب کاربر ذخیره می‌شوند و بین وب و اپ مشترک‌اند.

## شارژ محلی روی WiFi ایستگاه (بدون اینترنت)

مانند `edge-router.js` وب‌اپ، اپ لبه‌های محلی (Edge) را جست‌وجو می‌کند: فهرست لبه‌ها از سرور
(`SC_EDGE_PROBE_URLS`) و یک آدرس دستی در «تنظیمات ← آدرس سرور». وقتی گوشی روی WiFi ایستگاه است، نوار سبز
«لبه محلی … · شارژ بدون اینترنت» نمایش داده می‌شود و اسکن QR مستقیم روی لبه مجوز می‌گیرد، شارژ را شروع
می‌کند، وضعیت زنده را می‌خواند و توقف را ارسال می‌کند — حتی وقتی سرور ابری در دسترس نیست.

* هویت کاربر روی لبه: امضای روزانهٔ سرور (`X-SC-User-UUID` + `X-SC-Edge-Token`) که هنگام آنلاین بودن ذخیره
  می‌شود (۲۴ ساعت معتبر)، یا ورود با کد پیامکی که مودم خود ایستگاه می‌فرستد.
* صورتحساب جلسهٔ محلی پس از وصل شدن ایستگاه به اینترنت با سرور همگام و در سوابق ثبت می‌شود.

## پرداخت

با `PAYMENT_DRIVER=zarinpal` و `ZARINPAL_MERCHANT_ID` در سرور، صفحهٔ بانک در مرورگر باز می‌شود؛ پس از پرداخت
دکمهٔ «بازگشت به اپ» (لینک `safircharge://payment`) اپ را باز می‌کند و اپ نتیجه را از سرور تأیید می‌کند.
حالت `simulated` فقط برای توسعه است و در production پذیرفته نمی‌شود.

## اعلان‌ها

سرور برای پایان هر جلسهٔ شارژ، شارژ کیف پول و کمبود موجودی اعلان می‌سازد.

* **پوش واقعی (FCM):** در سرور `FCM_CREDENTIALS` (فایل JSON حساب سرویس Firebase) و در اپ هنگام build:
  ```bash
  flutter build apk --release --dart-define=FCM_PROJECT_ID=... --dart-define=FCM_API_KEY=... \
    --dart-define=FCM_SENDER_ID=... --dart-define=FCM_ANDROID_APP_ID=... --dart-define=FCM_IOS_APP_ID=...
  ```
  برای iOS کلید APNs را هم در کنسول Firebase بارگذاری کنید.
* **بدون Firebase:** اپ هر دقیقه (تا وقتی باز است) صندوق اعلان‌ها را می‌خواند و اعلان محلی گوشی نمایش می‌دهد.

## موقعیت مکانی و علاقه‌مندی‌ها

با اجازهٔ کاربر، موقعیت گوشی (حداکثر هر ۱۰ دقیقه) به سرور فرستاده می‌شود تا «نزدیک‌ترین ایستگاه‌ها» و فاصله‌ها
واقعی باشند؛ دکمهٔ «موقعیت من» روی نقشه. ایستگاه‌ها با ستاره به علاقه‌مندی‌ها اضافه و در نقشه فیلتر می‌شوند.

## اجرا

```bash
cd mobile
flutter pub get
flutter run --dart-define=API_BASE_URL=https://<آدرس-سرور-ابری>
```

* آدرس سرور در زمان build با `API_BASE_URL` تعیین می‌شود و کاربر می‌تواند آن را از صفحهٔ ورود (آیکون سرور)
  یا «تنظیمات ← آدرس سرور» تغییر دهد.
* شبیه‌ساز اندروید برای سرور محلی: `--dart-define=API_BASE_URL=http://10.0.2.2:8000`

## ساخت نسخهٔ انتشار

```bash
# اندروید (APK و Bundle گوگل‌پلی/کافه‌بازار)
flutter build apk --release --dart-define=API_BASE_URL=https://<سرور>
flutter build appbundle --release --dart-define=API_BASE_URL=https://<سرور>

# iOS — فقط روی macOS با Xcode
cd ios && pod install && cd ..
flutter build ipa --release --dart-define=API_BASE_URL=https://<سرور>
```

* شناسهٔ اپ: `ir.safircharge.app` (اندروید و iOS).
* امضای انتشار اندروید: `android/key.properties.example` را به `android/key.properties` کپی و مسیر keystore و
  رمزها را وارد کنید؛ بدون این فایل نسخهٔ release فقط برای تست با کلید debug امضا می‌شود.
* iOS: در Xcode تیم توسعه (Signing & Capabilities) را انتخاب کنید. متن مجوز دوربین در `Info.plist` ثبت شده است.

## QR شارژرها

اسکنر هر دو قالب را می‌پذیرد:

* آدرس کامل صفحهٔ شارژر وب‌اپ: `https://<سرور>/app/charger?station=ST-XXXX&connector=17&qr=<توکن>`
* فقط توکن QR (ایستگاه و کانکتور از روی توکن در سرور پیدا می‌شود).

مجوز شروع شارژ پس از اسکن به **حساب کاربر** (نه نشست مرورگر) گره می‌خورد و ۲۰ دقیقه معتبر است؛
بنابراین اسکن در اپ و شروع شارژ از وب (یا برعکس) هم کار می‌کند.

## تست

```bash
flutter analyze
flutter test
```

تست‌های سمت سرور API در `cloud/tests/Feature/MobileApiTest.php` قرار دارند (ورود با توکن، همهٔ صفحات،
اعتبارسنجی، شارژ کیف پول، مجوز QR و شروع/توقف شارژ از طریق OCPP ابری).

## محدودیت‌های فعلی

* تنظیم «زبان» (انگلیسی) در وب‌اپ هم پیاده نشده و رابط فقط فارسی است؛ در اپ این گزینه حذف شد.
* فهرست کانکتورهای آماده زیر اسکنر (مانند وب‌اپ) فقط در نسخهٔ توسعه نمایش داده می‌شود؛ در نسخهٔ انتشار باید QR
  واقعی اسکن شود.
